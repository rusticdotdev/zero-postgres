# Connection

A connection can be made with a URL string or `Opts`.

An URL can start with
- `pg://`
- `postgres://`
- `postgresql://`

The URL `pg://{USER}:{PASSWORD}@{HOST}:{PORT}/{DATABASE}?PARAM1=VALUE1&PARAM2=VALUE2` is equivalent to:

```rust,ignore
let mut opts = Opts::default();
opts.host = HOST;
opts.port = PORT;
opts.user = USER;
opts.password = Some(PASSWORD);
opts.database = Some(DATABASE);
opts.params.push((PARAM1, VALUE1));
opts.params.push((PARAM2, VALUE2));
```

See [`Opts`](https://docs.rs/zero-postgres/latest/zero_postgres/struct.Opts.html) for all available options.

## Sync

```rust,ignore
use zero_postgres::sync::Conn;

let mut conn = Conn::new("postgres://test:1234@localhost/test_db")?;
```

## Async

```rust,ignore
use zero_postgres::tokio::Conn;

let mut conn = Conn::new("postgres://test:1234@localhost/test_db").await?;
```

## Unix Socket

```rust,ignore
use zero_postgres::sync::Conn;
use zero_postgres::Opts;

let mut opts = Opts::default();
opts.socket = Some("/var/run/postgresql/.s.PGSQL.5432".to_string());
opts.database = Some("test".to_string());
let mut conn = Conn::new(opts)?;
```

## Upgrade to Unix Socket

By default, `upgrade_to_unix_socket` is `true`.

If `upgrade_to_unix_socket` is `true` and the TCP peer IP is local, the driver queries `SHOW unix_socket_directories` to get the Unix socket path, then reconnects using the socket for better performance.

For production, disable this flag and use explicit TCP or Unix socket:

```rust,ignore
let mut opts: Opts = "postgres://test:1234@localhost".try_into()?;
opts.upgrade_to_unix_socket = false;
let mut conn = Conn::new(opts)?;
```

## TLS Mode

| `TlsMode` | Authentication Method | Note |
|---|---|---|
| `Insecure` (default) | any | Convenient in a trusted local network |
| `Pki` | any | |
| `ChannelBinding` | SCRAM-SHA-256-PLUS only | Needs a short-lived or long password. Some signature algorithms are not supported. |
| `Hardened` | SCRAM-SHA-256-PLUS only |  |

If `opts.tls_config` is provided, it takes precedence.

### `Insecure`

The insecure mode uses whatever the server provides (opportunistic security).
If the server advertises TLS, use it without verifying the server cert. Otherwise do not use TLS.

TLS prevents a passive attack, but makes no difference to an active attack because anyone can send you a fake advertisement and downgrade TLS to non-TLS.


### Pki
The pki mode is the normal TLS we know. It verifies the received server cert against the trust chain.
The SAN field should be properly set up to include the hostname or IP.

### ChannelBinding
Channel binding is an alternative method to establish the TLS connection without a trust chain.

SCRAM relies on the fact that both the client and server know the password. The client sends a hash generated by the password and the server-provided salt.
Channel binding adds the hash of the server cert to SCRAM so that the MITM cannot provide its fake cert.

An attacker pretending to be a server can receive the hash and brute-force it later.
For a security strength of 192 bits, an alphanumeric random password should be at least 33 characters long.

### Hardened
The hardened mode uses both pki and channel binding.
An attacker needs to compromise both the trust chain and the password.
